# Experiment Harness Implementation Plan

> **For agentic workers:** Use the user-requested GPT-6.1 Sol subagents, with integration review by the orchestrator. The referenced superpowers execution skills are not installed; use the available collaboration tools.

**Goal:** Deliver the first complete, observable two-agent, three-round fixture with MongoDB persistence and a researcher dashboard.

**Architecture:** An application-owned scheduler admits each tool invocation before execution. Mastra supplies single-step inference and private persisted memory; MongoDB stores separate researcher evidence. A standalone worker survives browser disconnects, while a Node HTTP server exposes configuration and inspection APIs.

**Tech Stack:** TypeScript, pinned Mastra packages, MongoDB, Node HTTP, static browser JavaScript, Node test runner through tsx.

## Global constraints

- One active experiment agent and one active run at a time.
- Every admitted tool costs one unit, including validation failures, memory updates and end_turn.
- Private run/agent thread and resource identities; semantic recall and observational memory disabled.
- Condition pairs differ only in review text and operational identities; no implicit board delivery.
- Synthetic data only; no unrestricted agent code execution or external communication tools.
- Evidence failure stops execution; interrupted runs never resume automatically.
