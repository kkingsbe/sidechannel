Executive summary

This is a follow-up audit, not a re-run. The previous audit (45 findings, 4 critical) was followed by a nine-workstream remediation that closed every finding and created mechanical guardrails: an architecture census with budgets, a scenario/provider registry, port capability slices, adapter contract suites, a single dashboard transport, and a 59-entry decision log. Since then, 162 commits delivered wave-2 features (live timeline, turn pagination, codebook archive, pair comparison, run-evidence families, submit_report protocol) and a full dashboard redesign. The production tree grew from 149 files / 18,257 lines to 324 files / 29,450 lines, 73% of it dashboard. This audit re-measured every claim in that log instead of trusting it.

The skeleton held, and that is the headline. scripts/verify-boundaries.mjs and scripts/verify-composition.mjs pass. There is exactly one network fetch in the dashboard's 175 production files, and the six typed clients are composed in one provider. The harness, researcher and analysis repositories are genuine capability slices with shared contract suites. Provider and scenario registries are data, not decoration: the OCP test adds a provider with zero production edits. The status vocabulary is single-sourced with exhaustive tables that make a new status a compile error. Thirteen of fifteen structural budgets hold, the largest source file fell from 2,523 lines to 514, there are zero @ts-ignore, zero mutable module singletons, zero byte-identical duplicate files, and the largest cross-file duplicate block is 12 lines. All eight projects typecheck. That is a materially better architecture than the one the first audit described.

What came back is a different failure shape: duplication of logic, not of literals. The census counts copied constants, and constants are now well managed. The new copies are validators and derived predicates. One pair is judged comparable by two functions with contradictory rules — both shipped, so the same pair reads “comparable” in one tab and “not comparable” in another (C2). The healthcare artifact schema is validated by two owners that disagree about what happens when it is invalid. “Why is the primary action disabled” is authored six times with independent copy and independent predicates. The blind-review rule is derived three ways; status→tone is re-registered in a component and has already drifted from the canonical table. None of this is visible to the architecture census, which is the first thing to fix about the guardrails.

The god component is back, as a hook. Four closures now own several change axes each: useCodebookDraft (295 lines, 14 state, 45 returned members, five axes), useExperimentDraft (219 lines, persistence + ten commands + idempotency keys + navigation), WindowInspector (one 418-line function owning evidence, judgment form, blindness policy, save choreography and review history) and AnalysisSetupState (a 30-field props object five sections must accept whole). Each evidence tab additionally owns fetch + derivation + authored finding prose + presentation, and its riskiest logic — regexes that assert an agent’s report contradicts the record — is untestable because it lives in a .tsx. The page-entry shells did stay honest (16–160 lines), so the problem moved one level down rather than returning.

The extensibility seams the core got right were not applied to the new surfaces. Tool admission is expressed three times — JSON-Schema catalog, an allow-key table and an if chain — so adding a tool is a four-site edit (S4, explicitly deferred, still open). The evidence-tab dispatcher is a five-branch if-chain over a vocabulary the contracts layer already closes, while the correct keyed registry sits one directory away. The experiment editor keeps a parallel section list and hardcodes its review step as the literal 6. runtimePlugins claims “registry data only” and switches with a fail-open default. And both failing budgets were crossed by post-remediation commits that did not consult the guardrail — a 195-line dead duplicate of the evidence family is still sitting in panels.tsx.

The typed dashboard is cast-deep, and the adapter parity gaps moved somewhere the suites do not look. The page envelope is declared three times; the “typed per tab” evidence client is three casts; pair() and evaluation() return Promise<unknown>; there are 34 as unknown as casts in production code. Below the UI, the contract suites prove adapter agreement on the cases they contain — and three real divergences live outside them: the memory research store sorts locale-aware but filters ordinally (a cursor can skip a row), the evidence-key coercion contract is honoured only by Mongo (a /evidence/artifacts/07 link resolves in production and 404s in memory-backed tests), and run-list tie ordering differs for exactly the paired runs the product creates. These are the same class of defect the first audit rated most dangerous.

Verdict: C+ (up from C), and for a different reason than before. Violation density fell by roughly a quarter — 45 findings over 18.3k lines is 2.46 per 1k; 53 over 29.5k is 1.80 — and the remaining criticals are concentrated rather than systemic: one inverted dependency direction inside the dashboard and one policy with two contradictory implementations. The P0 list is small and mostly deletion or two-line imports; the P1 list is where the cost now lives, because it is the shape that will make the next wave of features expensive.

What is working well

These are not consolation prizes: they are the constraints the next refactor must preserve, and several of them are the reason this audit could verify claims rather than guess.

Dependency direction and composition roots are machine-enforced

Nx layer tags plus a custom import rule reject cross-layer, cross-service, undeclared-export and browser/server leaks; verify-boundaries.mjs proves the rule with fixture sources and compiles the browser contract graph without Node declarations. verify-composition.mjs proves no concrete adapter is built in a worker or route, no lazy provider import, no mutable Mastra global. Both were re-run during this audit: both pass.

The read path really is one seam

Exactly one fetch in 175 dashboard production files, one ApiError shape, one query builder, six typed clients composed in ApiClientProvider, and one read implementation (lib/clients/query.ts) with a generation counter, stale-response defence and a documented empty-page identity. The residual leaks are paths, not requests (H17) — which is why the fix is additive.

Ports are sliced and the slices are proven

Repository is four capability slices, ResearcherRepository five, AnalysisRepository five, and the analysis worker port deliberately excludes codebooks. The same contract suite runs against memory and Mongo (port-contracts.*), and the consumers take Picks rather than the aggregate. The remaining wide ports (H20, M14) are exceptions, not the rule.

Registries are data, and the vocabulary is exhaustive

Provider and scenario catalogs are derived from one declaration, and the OCP test registers a new provider through data only. lib/status.ts keys every status table by the contract union, so a new status is a compile error until described. ViewRegistry<TabId> renders unknown tabs as NotFound instead of a silent fallback. Twelve canonical vocabulary tables are single-sourced; only three ad-hoc sites survive.

Corpus hygiene is genuinely good for a tree this size

Zero @ts-ignore, zero @ts-expect-error, zero byte-identical duplicate files, zero mutable module singletons, a 12-line cap on cross-file duplication, all eight projects typechecking clean, and 128 test files. These are the numbers that make the rest of the findings credible: the repository is not sloppy, it is growing faster than its guards.

The remediation's deletions survived, and the shells stayed honest

The largest source file fell from 2,523 lines to 514; every page entry is now a 16–160 line router shell with no data hooks; the four original god components are gone and their behaviour is pinned by page tests. The reason to trust the earlier program is that its structural results are still measurable two waves later.

There is a real decision log, and it is mostly accurate

59 entries recording ownership, accepted deviations, status changes and gate evidence. It let this audit verify claims cheaply — and it is how the two stale entries (fixture count, deferred-item status) were identified. A repository that writes down why it did not fix something is rare, and it is the main reason this second audit could be specific rather than generic.

  • Read-only static audit: no repository file was modified.   • Infrastructure-free gates were executed: node scripts/verify-boundaries.mjs passes, node scripts/verify-composition.mjs passes, node scripts/architecture-budget.mjs --check exits 1 with two budget violations (reproduced), and tsc --noEmit passes for all eight projects after building the three shared packages. npm run check/npm test cannot execute in this sandbox because NX forks child processes and the sandbox denies the spawn (EPERM); that is an environment boundary, not a code signal, and is reported as such.
  • Census frame: 324 production TypeScript files / 29,450 lines across the seven source roots, plus 128 test files / ~10,900 lines. Excludes node_modules, dist, .nx and the .claude worktree copies. Counts were produced by re-running the repository's own census script and by read-only greps/shingle scans; the exact values quoted are command output, not estimates.
  • The audited tree moved once, mid-audit: a concurrent pull replaced the local head 07e85da with origin/main at fd07454 (113 files, mostly dashboard CSS and the framed-sheet redesign).
